# Tutorial interactivo para clientes

El tutorial enseña el uso de Tabelio mediante un espacio de práctica con datos ficticios, cursor visible y explicaciones paso a paso. Está disponible después de iniciar sesión, en **Aprender a usar la app** del menú lateral o directamente en `/tutorial`.

Los formularios y resultados pertenecen a una simulación dentro del navegador. Guardar, eliminar, generar documentos, analizar con IA, registrar firmas y enviar información en el tutorial no modifica expedientes ni ejecuta servicios reales. El enlace **Abrir esta sección de la aplicación** permite salir de la práctica hacia el módulo correspondiente.

## Empezar y controlar el recorrido

1. Abre **Aprender a usar la app**.
2. Selecciona **Iniciar demostración** para observar el recorrido o **Iniciar práctica** para realizar las acciones tú mismo.
3. También puedes abrir un capítulo concreto desde el índice.
4. Usa **Volver al índice** o **Salir** para detener el recorrido. **Retomar recorrido** recupera el punto guardado en ese navegador.

### Demostración automática

El cursor se desplaza hasta el botón del ejercicio, se muestra el clic y aparece el resultado ficticio. Después de la explicación se inicia la cuenta regresiva para el siguiente paso. Puedes elegir velocidad de 0.75×, 1×, 1.5× o 2×.

El recorrido se pausa al editar un campo, cambiar de pestaña o abrir un diálogo modal. Se reanuda con **Continuar**. Si el objetivo del clic cambia o no está disponible, el reproductor se detiene y permite continuar manualmente o saltar el paso.

### Práctica guiada

El tutorial espera tu acción. Completa los campos indicados, elige los valores del ejemplo y pulsa su botón. Los ejercicios de confirmación requieren marcar que revisaste los datos. Los filtros y selecciones comprueban que se haya usado el valor indicado por el ejercicio.

Cuando terminas la acción se habilita **Siguiente**. La práctica no avanza por tiempo; puedes leer, repetir o saltar a tu ritmo. Cambiar de modalidad pausa y reinicia el ejercicio actual para practicarlo en el nuevo modo.

### Controles disponibles

| Control | Comportamiento |
| --- | --- |
| Anterior / Siguiente | Recorre los pasos. En práctica, Siguiente espera la acción del ejercicio. |
| Pausar / Continuar | Detiene o reanuda el clic automático, la voz y la cuenta regresiva. |
| Saltar explicación | Avanza al paso siguiente y conserva como omitido el que no se haya completado. |
| Saltar capítulo | Omite los pasos restantes del capítulo y abre el siguiente. |
| Elegir capítulo | Abre directamente su primer paso y pausa el reproductor. |
| Modalidad | Cambia entre demostración y práctica. |
| Velocidad | Ajusta el ritmo de la demostración. |
| Escuchar explicación | Activa la narración opcional con una voz local en español disponible. |
| Salir / Volver al índice | Detiene el recorrido y muestra el índice sin perder el avance. |

**Espacio** pausa o continúa y **Esc** sale del recorrido cuando no estás escribiendo en un campo. Los botones permanecen disponibles para usar teclado, mouse o pantalla táctil. El movimiento respeta la preferencia de movimiento reducido del sistema.

La narración usa únicamente voces españolas marcadas como locales por el navegador. No necesita un proveedor de IA, no pide acceso al micrófono y no genera consumo. Si no hay una voz compatible, la opción queda deshabilitada y las explicaciones escritas siguen disponibles. Mientras habla la voz, la cuenta regresiva espera.

## Progreso y datos

El progreso se guarda en `localStorage` con una clave separada por **organización, cuenta, perfil y versión del catálogo**. Conserva el capítulo y paso, modalidad, velocidad, pasos completados y omitidos, y estado final. Los valores escritos en los formularios de práctica, archivos ficticios y explicaciones narradas no se persisten como parte del progreso.

Al retomar se validan la versión y los identificadores contra el catálogo permitido para el perfil. Los datos inválidos o de otra versión se descartan. Si el navegador bloquea el almacenamiento, el recorrido funciona durante la visita y muestra que el avance no podrá guardarse. Iniciar una nueva demostración o práctica desde el inicio reinicia ese recorrido.

Para preparar el contenido, la página consulta la identidad autenticada y el perfil mediante `/auth/me`. El reproductor y el espacio de práctica no llaman APIs de negocio ni consultan registros reales, IBM, OCR o modelos de IA. Los importes de presupuesto y consumo mostrados son ilustrativos. El asistente flotante real se oculta en `/tutorial` para mantener separadas las acciones de práctica.

## Ampliar o mantener el tutorial

Los archivos principales son:

- `apps/web/lib/tutorial-catalog.ts`: tipos, capítulos, pasos, roles y versión.
- `apps/web/components/tutorial-course.tsx`: entrada, índice, progreso y navegación.
- `apps/web/components/tutorial-workspace.tsx`: pantallas y formularios ficticios.
- `apps/web/components/tutorial-player.tsx`: cursor, clics, voz, reloj y controles.
- `apps/web/lib/tutorial-player.ts`: validación de objetivos y reglas del reloj.
- `apps/web/lib/tutorial-progress.ts`: almacenamiento y validación de progreso.
- `apps/web/lib/tutorial-exercise.ts`: validación de filtros y selecciones del ejercicio.

Para añadir una función:

1. Agrega un paso al capítulo correspondiente usando un identificador estable. Define título, explicación, instrucción, resultado, acción y texto del botón. Los campos y previews deben contener exclusivamente ejemplos ficticios.
2. Usa `roles` en el capítulo y, cuando sea necesario, en cada paso. Comprueba los permisos reales del dominio; no presentes una escritura o aprobación reservada como disponible para un perfil de consulta.
3. Define `durationSeconds` según la lectura del texto o utiliza el cálculo predeterminado del catálogo. Conserva las explicaciones concretas y el propósito de la acción.
4. Establece `route` como entrada estática de un módulo, por ejemplo `/expedientes`. No uses URLs externas, rutas `/api`, tokens del portal ni identificadores de expedientes reales.
5. Si hace falta una pantalla nueva, amplía el workspace mediante estado local. No conectes los handlers de la práctica a servicios de negocio, sesiones IBM, IA, descargas reales o funciones de la aplicación que guarden cambios.
6. Si cambia de forma incompatible la estructura o el significado del recorrido, incrementa `TUTORIAL_CATALOG_VERSION`. Esto separa el progreso de la nueva versión del anterior.

El helper del catálogo construye `id` y `target` únicos a partir del capítulo y del paso. El botón de práctica debe conservar estas tres marcas además de `type="button"`:

```tsx
<button
  type="button"
  data-tutorial-target={step.target}
  data-tutorial-action={step.id}
  data-tutorial-demo-safe="true"
  onClick={performLocalPracticeAction}
>
  {step.buttonLabel}
</button>
```

El reproductor busca el objetivo exclusivamente dentro de la referencia del workspace. Verifica identidad de acción, tipo de botón, marca de seguridad y que no esté deshabilitado, oculto o inerte. Nunca debe ampliarse la búsqueda al documento completo para activar botones reales. Si la acción cambia o falta, el comportamiento correcto es pausar y explicar el problema.

Tras un cambio, ejecuta `npm run lint -w @despacho/web` y `npm run test -w @despacho/web`. Revisa además demostración, práctica, pausa, cambio de modalidad, salto de paso/capítulo, regreso al índice, recarga y retoma, y el comportamiento con una pantalla estrecha. Comprueba que las acciones del recorrido no generen peticiones de negocio ni consumo de IA.
